# 뉴스 수집기 기능 개발 워크플로
AI뉴스수집기 앱에 새 기능을 개발할 때 브랜치 생성부터 커밋·병합·요약까지 순서대로 진행합니다.
브랜치이름: $ARGUMENTS

## 실행순서

### 1. 현재 상태 확인
- `git status`와 `git branch --show-current`로 현재 상태와 브랜치를 확인한다.
- main 브랜치가 아니라면 경고를 주고, main으로 이동할지 사용자에게 물어본다. 사용자가 동의하기 전에는 이동하지 않는다.
- 커밋되지 않은 변경 사항이 있으면 함께 알려준다.

### 2. 새 브랜치 생성
- `$ARGUMENTS`가 비어 있지 않으면 그 이름으로 브랜치를 만든다.
- 브랜치 이름을 입력받지 못했다면 어떤 기능을 개발할 것인지 사용자에게 물어보고, 답변을 바탕으로 영어 소문자-하이픈 형식(예: `category-crud`)의 브랜치 이름을 제안한다. 사용자가 확인하면 그 이름으로 만든다.

### 3. 개발 시작 안내
- 브랜치 생성이 끝나면 "이제 개발을 시작하세요 !"라고 안내한다.
- `CLAUDE.md`를 읽고 이 프로젝트의 기술 스택과 컨벤션을 다시 한번 요약해서 알려준다. (예: Next.js 16 + Clerk 인증 + Neon/Drizzle + Anthropic Claude + Notion REST API, UI 작업 전 `ui.md` 확인, Next.js 코드 작성 전 `node_modules/next/dist/docs/` 확인, 앱 이름 표기 "AI뉴스수집기", 비밀 값은 환경 변수로 서버에만 둠)

### 4. 완료 처리
- 사용자가 "완료" 또는 "done"이라고 입력하면 다음을 진행한다.
  1. `git status`와 `git diff --stat`으로 변경된 파일 목록을 보여준다.
  2. 변경 내용을 바탕으로 한국어 커밋 메시지를 자동으로 제안한다. (기존 커밋 로그의 스타일을 따른다)
  3. 사용자가 확인하면 변경 파일을 스테이징하고 커밋한 뒤, main으로 이동해 작업 브랜치를 병합한다.
- 사용자가 확인하기 전에는 커밋하거나 병합하지 않는다. 병합 중 충돌이 나면 멈추고 사용자에게 알린다.

### 5. 작업 요약
- 병합이 끝나면 작업 내용을 요약해서 보여준다. (브랜치 이름, 커밋 메시지, 변경된 파일, 주요 변경 내용)
