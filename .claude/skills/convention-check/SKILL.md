# 커밋 전 컨벤션 검토

커밋 전에 변경된 코드의 컨벤션 준수 여부와 품질을 검토한다.

## 절차

1. 현재 브랜치에서 변경된 코드를 가져온다.
   - `git status`로 변경된 파일 목록을 확인한다.
   - `git diff HEAD`로 스테이징된 변경과 아직 스테이징되지 않은 변경을 함께 확인한다.
   - 추적되지 않는 새 파일은 내용을 직접 읽어 검토 대상에 포함한다.
2. [convention.md](convention.md)의 규칙을 기준으로 변경된 코드를 항목별로 검토하고, 각 항목을 '통과' 또는 '개선 필요'로 표시한다.
3. '개선 필요' 항목이 있으면 해당 파일과 위치, 어떻게 수정해야 하는지를 코드 예시(수정 전/후)와 함께 알려 준다.
4. 모든 항목이 '통과'라면 '커밋 준비가 완료되었습니다. !'를 출력한다.

## 출력 형식

| 구분 | 항목 | 결과 |
| --- | --- | --- |
| 네이밍 | 변수명·함수명 카멜 케이스 | 통과 / 개선 필요 |
| 네이밍 | 컴포넌트명 파스칼 케이스 | 통과 / 개선 필요 |
| 네이밍 | 상수 UPPER_SNAKE_CASE | 통과 / 개선 필요 |
| 포매팅 | 들여쓰기 2칸 | 통과 / 개선 필요 |
| 포매팅 | 한 함수 하나의 역할 | 통과 / 개선 필요 |
| 코드 품질 | console.log 제거 | 통과 / 개선 필요 |
| 코드 품질 | 하드코딩된 값의 환경변수 분리 | 통과 / 개선 필요 |
| 코드 품질 | DB 조작 코드 try-catch | 통과 / 개선 필요 |
| 코드 품질 | 오류 응답의 HTTP 상태코드 | 통과 / 개선 필요 |

변경된 코드에 해당하는 내용이 없는 항목은 '통과'로 표시한다.
